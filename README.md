# KAVACH 4.0 Voice Assistant — Android Project

Package name: `com.cmdtaj.kavach4assistant`

A bilingual (English / Hindi) offline voice-and-text reference app for
loco pilots, covering KAVACH 4.0 subsystems, startup procedure,
operating modes, SOS handling, collision scenarios, and safety rules.

**Architecture note:** this is a native Android WebView shell (plain
Gradle/Android Studio project, not Capacitor). Android's WebView does
not reliably support the browser Web Speech API — `SpeechRecognition`
mostly doesn't work in WebView at all, and `speechSynthesis` is
inconsistent across devices. So voice input/output uses Android's
native `SpeechRecognizer` and `TextToSpeech`, exposed to the bundled
web app through a small JavaScript bridge
(`app/src/main/java/.../AndroidBridge.java`). The web app's original
browser-based Web Speech logic is kept as an automatic fallback (used
only if `window.AndroidBridge` isn't present — e.g. if you open
`app/src/main/assets/www/index.html` directly in a desktop browser to
preview it).

### About the Gradle wrapper JAR

`gradle/wrapper/gradle-wrapper.jar` (a small binary file) is **not**
included, since it has to be generated by an actual Gradle
installation rather than hand-written. Do either of these once, from
the project root:

- Open the project in Android Studio — it detects the missing wrapper
  JAR and offers to regenerate it automatically, **or**
- If you have Gradle installed locally: `gradle wrapper --gradle-version 8.7`

After that, `./gradlew` works normally for every command below.

## 3. Build instructions

### Fastest path: build a real APK with no local install (GitHub Actions)

This project includes `.github/workflows/build-apk.yml`, which builds
a real, installable debug APK on GitHub's own servers — useful if you
don't want to install Android Studio just to get an APK to test.

1. Push this project to a GitHub repository.
2. Open the repo's **Actions** tab (the workflow runs automatically on
   push, or click **Run workflow** to trigger it manually).
3. When the run finishes, open it, scroll to **Artifacts**, and
   download `kavach4-debug-apk` — that zip contains a real
   `app-debug.apk`.
4. Install it on a phone: copy it over and tap to install (allow
   "install from this source" when prompted), or
   `adb install app-debug.apk` over USB.

This produces the **debug** APK only (unsigned, uses AdMob test IDs
unless you've committed a real `admob.properties`). For a signed
release AAB to upload to Play Store, either extend the workflow with
your keystore as GitHub Secrets, or build locally as below.

### Open in Android Studio (for release builds / active development)

1. `File -> Open` and select the `kavach4-android` folder.
2. Let Gradle sync (first sync downloads dependencies — needs
   internet).
3. `Build -> Build Bundle(s) / APK(s) -> Build APK(s)` for a debug
   APK, or `Build -> Generate Signed Bundle / APK` for a release
   AAB/APK.

### Command line

```bash
cd kavach4-android

# Debug APK (unsigned test build, installable directly via adb)
./gradlew assembleDebug
# Output: app/build/outputs/apk/debug/app-debug.apk

# Release APK
./gradlew assembleRelease
# Output: app/build/outputs/apk/release/app-release.apk

# Release AAB (what you upload to Google Play)
./gradlew bundleRelease
# Output: app/build/outputs/bundle/release/app-release.aab
```

Release builds are only signed if `keystore.properties` exists (see
§6). Without it, `assembleRelease`/`bundleRelease` still succeed but
produce an **unsigned** artifact — fine for local testing, but the
Play Console will reject an unsigned AAB.

## 4. AdMob setup

The app ships wired for Google's **official test IDs** by default, so
it builds and shows real (test) ad traffic immediately — no AdMob
account needed to build and run.

**Test App ID:** `ca-app-pub-3940256099942544~3347511713`
**Test Banner ID:** `ca-app-pub-3940256099942544/6300978111`

### Switching to your real AdMob IDs

1. Create an AdMob account at https://admob.google.com and register
   the app (App name: "KAVACH 4.0 Voice Assistant", package:
   `com.cmdtaj.kavach4assistant`).
2. Create a **Banner** ad unit for the app.
3. Copy `admob-config.example` to `admob.properties` in the project
   root:
   ```bash
   cp admob-config.example admob.properties
   ```
4. Edit `admob.properties` and replace both values with your real
   AdMob App ID and Banner Ad Unit ID.
5. Rebuild. `app/build.gradle` reads `admob.properties` automatically
   at build time and injects the App ID into `AndroidManifest.xml`
   (via `manifestPlaceholders`) and the Banner ID into
   `BuildConfig.ADMOB_BANNER_ID` (used by `MainActivity.setupAdBanner()`).

`admob.properties` is git-ignored — your real IDs never get committed
alongside `admob-config.example`.

### Verifying ads before publishing

- **While `admob.properties` still holds test IDs**: every device
  shows Google's clearly-labeled "Test Ad" banner. This is expected
  and confirms the AdMob SDK, layout, and ad-request flow all work.
- **After switching to real IDs**: add your test device as an AdMob
  test device (AdMob console -> your ad unit -> or check Logcat for a
  line like `Use RequestConfiguration.Builder().setTestDeviceIds(...)`
  which prints your device's test ID) *before* clicking real ads
  yourself — clicking your own live ads without registering as a test
  device violates AdMob policy and can get your account suspended.
- Confirm the banner loads without pushing the microphone button or
  any KAVACH content off-screen on a few different screen sizes/
  emulators (this is what `activity_main.xml`'s weighted layout is
  designed to guarantee, but always verify visually).

### If the ad fails to load

`MainActivity`'s `AdListener.onAdFailedToLoad()` sets the whole ad
container to `GONE`, so the WebView reclaims that space and the app
works exactly as if ads were never present — no crash, no blank gap.

### Monitoring earnings

Once live, open https://admob.google.com and check the **Overview**
or **Apps** tab for impressions, clicks, and estimated earnings —
updated with roughly a one-day reporting delay. There is no way to
guarantee or predict earnings; they depend entirely on traffic,
region, and advertiser demand.

## 5. Permissions explained

| Permission | Why the app needs it |
|---|---|
| `RECORD_AUDIO` | Lets the user ask questions by voice via Android's native speech recognizer. Only requested when the mic button is tapped; the app works fully via typed/searched text if denied. |
| `INTERNET` | Required by the AdMob SDK to fetch ad creatives, and by some Android devices' cloud-based speech recognition backend. The KAVACH knowledge base itself never needs internet. |
| `ACCESS_NETWORK_STATE` | Standard AdMob SDK requirement, used to adapt ad requests to current connectivity. |

No location, contacts, storage, camera, or any other permission is
requested.

## 6. Signing the release build

1. Generate a keystore (do this once, and back the `.jks` file up
   somewhere safe outside of git — losing it means you can never
   publish an update to the same Play listing again):
   ```bash
   keytool -genkeypair -v -keystore kavach4-release.jks \
     -alias kavach4 -keyalg RSA -keysize 2048 -validity 10000
   ```
   Place the resulting `kavach4-release.jks` one directory above
   `kavach4-android/` (or adjust the path in the next step).
2. Copy the template and fill in your real values:
   ```bash
   cp keystore.properties.example keystore.properties
   ```
3. Build: `./gradlew bundleRelease` now produces a signed
   `app-release.aab`.

## 7. Play Store preparation checklist

- [ ] Real AdMob App ID / Banner ID in `admob.properties` (§4)
- [ ] Signed release AAB via `keystore.properties` (§6)
- [ ] `versionCode` / `versionName` bumped in `app/build.gradle` for
      every subsequent release (versionCode must always increase)
- [ ] App icon: the bundled adaptive icon
      (`res/drawable/ic_launcher_*.xml`, `res/mipmap-anydpi-v26/`) is a
      simple placeholder signal-lamp mark on the KAVACH color palette.
      Replace it with your final branding via Android Studio's
      `Image Asset` wizard (`res -> New -> Image Asset`) before
      publishing, or hand it to a designer to produce a full icon set
      (this also backfills legacy PNG mipmaps for devices below the
      adaptive-icon API level).
- [ ] Splash screen (`res/drawable/splash_background.xml`) — swap the
      placeholder mark for your final logo the same way.
- [ ] Privacy policy hosted at a **public URL** (Play Console requires
      this even though the app also bundles `privacy_policy.html`
      offline) — update `play_store_url` and `privacy_policy_url` in
      `res/values/strings.xml` once you have real values, e.g. by
      publishing `app/src/main/assets/www/privacy_policy.html` as a
      GitHub Pages page or any static host.
- [ ] Store listing assets (screenshots, feature graphic, short/full
      description) — not part of this project; prepare separately in
      Play Console.
- [ ] Content rating questionnaire completed in Play Console.
- [ ] Data safety form in Play Console — declare: microphone audio
      (processed on-device / by the OS speech service, not stored or
      transmitted by this app), and note AdMob's own data collection
      (Play Console can usually pull this automatically once the
      Mobile Ads SDK is detected).

### Uploading

Play Console -> your app -> **Production** (or **Internal testing**
first, recommended) -> **Create new release** -> upload
`app-release.aab` -> fill in release notes -> **Review and roll out**.

## 8. Troubleshooting

**Gradle sync fails / "SDK location not found"**
Create `local.properties` in the project root (Android Studio does
this automatically) with `sdk.dir=/path/to/Android/Sdk`.

**`gradle-wrapper.jar` missing / `./gradlew` fails immediately**
See "About the Gradle wrapper JAR" in §1 — open in Android Studio once
to auto-generate it, or run `gradle wrapper --gradle-version 8.7`.

**Build fails with a Java version error**
Ensure JDK 17 is selected: Android Studio -> Settings -> Build,
Execution, Deployment -> Build Tools -> Gradle -> Gradle JDK.

**App installs but the mic button does nothing**
Check Logcat for a `RECORD_AUDIO` permission denial, or that the
device actually has "Android System Speech Recognition" (or Google
app) installed and set as the default assistant/speech service — a
few budget devices or custom ROMs ship without it. The app's text
input and search always work regardless.

**Ads never load, even test ads**
Confirm `INTERNET`/`ACCESS_NETWORK_STATE` permissions are present in
the manifest (they are, by default) and the device/emulator actually
has network access. Emulators need Google Play system images, not the
plain AOSP ones, for the Mobile Ads SDK to function reliably.

**Hindi text renders as boxes/tofu**
This should not happen on any Android 8.0+ device (minSdk 26) — Noto
Sans Devanagari ships as a system font. If you see it on a very old or
heavily customized device, check that the OEM hasn't stripped Indic
font support from the system image.

**"App not installed" when sideloading a debug + release build
together**
The debug build has an `applicationIdSuffix ".debug"`
(`com.cmdtaj.kavach4assistant.debug`) specifically so it can coexist
with a release install of the real package ID — if you still see
this, uninstall any previous conflicting install and retry.

## 10. What was added/changed for Android

- Native speech recognition + text-to-speech via `AndroidBridge`
  (browser Web Speech kept only as a non-Android fallback).
- A dedicated "Search KAVACH topics" bar that filters the topic grid
  live.
- Removed the external Google Fonts CDN link so the app never depends
  on network access for its base UI (offline-first, per spec).
- Footer actions: Share app, Rate app, About, Privacy policy — wired
  to native Android intents/dialogs.
- AdMob banner, back-button handling (WebView history, then
  double-press-to-exit), RECORD_AUDIO permission flow, splash screen,
  adaptive app icon.
